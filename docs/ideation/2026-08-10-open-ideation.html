Grounding Context

Codebase Context. headroom-plugin instruments an external Python "headroom" compression engine for Claude Code. Components: two plugin-native hooks (scripts/hcat-gate.sh, PreToolUse on Read|Bash; scripts/dangi-hook.sh, PostToolUse on *), the bin/hcat CLI wrapper (compress-at-source with a receipt line + stats event), scripts/statusline.sh (transcript-parsing savings badge priced from data/model-prices.json), scripts/doctor.sh (read-only health check, --fix opt-in), and two conversational skills. Conventions: fail-silent hooks ("MUST always exit 0"), GNU/BSD portability, dual install modes (plugin vs legacy). Known gaps confirmed in-repo: the ~10K-char hook-payload truncation lets the biggest blobs evade Dangi (SKILL.md step 8); the gate's extension allowlist and bare-cat detection are deliberately narrow; test coverage is statusline-only (test.sh, 1264 lines); doctor detects but cannot fix legacy hooks in settings.local.json or project settings; the "counts as compression" attribution logic exists twice (jq in statusline, shell regex in dangi-hook). Release pattern: every v2.5/v2.6 feature merge was followed by a hardening pass citing review findings.

External Context (web research, value: high). The niche is no longer greenfield: Claude Context Mode, Toonify MCP, and CompressMCP all ship compression MCPs — CompressMCP even ships a session-savings status bar, so the badge alone is not a moat. Compression ratios are table stakes. Unclaimed positions the research surfaced: unifying "compress in place" vs "delegate to a sub-agent" (Anthropic's own context-engineering guidance treats sub-agent isolation as the primary lever); TOON-style lossless structural reformatting (30–60% on uniform JSON, stackable, unused here); priced waste (loss framing) rather than priced savings; and team/social framing of savings. In-terminal, in-the-moment feedback remains headroom's distinctive ground vs dashboard-layer cost tools.

Process notes. Learnings search skipped (no docs/solutions/ exists). All candidate bases were adversarially checked by a fresh-context verifier that read the repo; one popular premise was refuted (the statusline does not currently compute context-window fill) and several "the data already exists" claims were corrected before ranking.

1. Context-strategy router: compress vs delegate, sized on truth

Confidence 80%Complexity Medium
Description
Two moves that only work together. First, fix the documented blind spot: Dangi currently sizes .tool_response, which Claude Code truncates (~10K chars) before hooks see it — so the largest blobs evade the nudge. The hook also receives tool_input: for Read it has file_path, and for Bash it already extracts the structured-file token — so stat the named file and trigger on max(response bytes, file bytes). Second, once true size is known, make the nudge a sized three-way router instead of one-size advice: small → ignore; medium structured → hcat/headroom_compress; huge or non-file-backed → "read it inside a disposable subagent that returns only the compressed text." Finally, credit followed delegations in the badge, so the behavior the plugin recommends stops making the badge look worse.
Basis
direct: dangi-hook.sh:127 already emits the subagent option as a trailing clause with no decision rule (verifier-confirmed verbatim); SKILL.md step 8 documents the truncation evasion; dangi-hook.sh:44-48 sizes only .tool_response while :119-122 already extracts the file path — but only after the size check passed. external: Anthropic context-engineering guidance treats sub-agent isolation as the primary context lever; the research digest found no tool unifying "delegate vs compress."
Rationale
This converts the plugin's single admitted real-time weakness into its most differentiated capability, and stakes out the one competitive position the research found unclaimed. It also repairs a live incentive contradiction: today, an agent that follows Dangi's best advice (delegate) earns zero badge credit.
Downsides
Attributing subagent reads to a savings number is estimation, not receipt-verified counting — it needs an honest "estimated" treatment to protect the badge's credibility. stat on Bash-extracted paths needs safe handling for non-file-backed output.

2. The gate that answers — rewrite or serve, with a lossless TOON-lite floor

Confidence 75%Complexity Medium
Description
The gate currently denies a large read, prints the exact replacement command as prose, and hopes the model complies — spending a full round trip, and leaking raw bytes on retry via the once-per-file escape hatch. Claude Code PreToolUse hooks support updatedInput: for the Bash-cat case, silently rewrite the command to invoke hcat and allow it in one shot. For the Read case (tool type can't be swapped), run hcat on the deny path and embed the compressed rendering + receipt directly in the deny reason — the "denial" is the answer. Underneath both, add a dependency-free jq/awk TOON-style lossless reformatter as hcat's fallback tier (strategy:"toon-lite"): uniform JSON arrays become a header row + CSV-like rows, worth 30–60% with zero semantic risk — so the <5% passthrough dead zone and even engine-less installs still deliver savings.
Basis
direct: hcat-gate.sh:96-98 builds the replacement command then discards it as prose; :79-81 lets raw bytes through on retry; bin/hcat:93-98 prints raw bytes verbatim on passthrough (all verifier-confirmed). external: updatedInput in PreToolUse hookSpecificOutput verified real in Claude Code hook docs; TOON format (30–60% lossless on uniform JSON, stackable with semantic compression).
Rationale
Converts the weakest link (model compliance) into a non-issue and halves the token cost of every gated read. The verifier rated this the most concretely feasible synthesis in the set. TOON-lite also fixes the worst onboarding moment: a fresh install with no Python engine currently delivers zero value.
Downsides
Silent command rewriting affects user trust and debuggability — it needs a visible receipt so the substitution is never mysterious. Embedding compressed content in a deny reason bumps against reason-size limits and needs testing.
Today: deny and hope
  1. Claude runs cat big.json
  2. Gate denies, explains what to run instead
  3. Claude re-plans, runs hcat big.json (or retries — raw bytes leak)
  4. Two round trips; compliance optional
Proposed: rewrite or serve
  1. Claude runs cat big.json
  2. Gate rewrites to hcat big.json via updatedInput, allows
  3. Compressed output + receipt arrive in one shot
  4. No engine? TOON-lite still reformats losslessly

3. Ambient health: a "broken" badge state + SessionStart micro-doctor

Confidence 85%Complexity Low
Description
The fail-silent hook discipline ("MUST always exit 0, print nothing") means a broken engine, vanished Python, or jq failure makes compression silently stop — and the badge sits on idle-red forever, indistinguishable from "nothing needed compressing." Three small pieces: hooks and hcat write a last-error file to the state dir on internal failure; the statusline renders a distinct broken glyph pointing at /doctor (doctor clears it on a passing run); and a <100ms SessionStart hook runs the fast subset of doctor (jq present, engine resolves, price table parses), staying silent when healthy and injecting one line only on failure. Optionally, restructure doctor as a check registry with --json output so any surface can poll health.
Basis
direct: both hook headers carry the exit-0 discipline (verifier-confirmed); hooks/hooks.json registers only PreToolUse and PostToolUse — no SessionStart entry; hcat has exit codes 3/4 ("python missing" / "compression failed") that nothing surfaces ambiently. external: SessionStart is a real Claude Code hook event (verified).
Rationale
An ambient indicator whose failure mode mimics its idle state is the worst possible failure for an ambient product. "How long has compression been broken on your machine without you knowing?" currently has no answer. The state-dir and statusline plumbing already exist — this is small work closing the biggest trust gap.
Downsides
SessionStart probes add startup latency budget to every session; the check subset must stay ruthlessly fast. A stale last-error that outlives the actual problem would cry wolf — clearing semantics need care.

4. Session invoice + append-only savings ledger (Stop hook)

Confidence 70%Complexity Medium
Description
Add a Stop/SessionEnd hook that walks the session transcript — the untruncated ground truth — and appends one structured JSONL event stream: saves (tagged by attribution kind: hcat first-pass vs MCP-deferred), and priced misses ("this session burned ~$0.42 on 3 uncompressed blobs", with file paths). The statusline's transient missed count graduates into a durable, loss-framed record. Downstream surfaces become trivial consumers of the ledger: a next-session one-line invoice, doctor --audit (reconcile lifetime totals against transcripts — today they're an unverified sum of loose files), and later a weekly/team digest. Note: miss byte-sizes are not currently summed anywhere — the ledger pass adds that tracking.
Basis
direct: hooks/hooks.json has no Stop hook; statusline.sh:172-177 shows lifetime totals as an unreconciled awk sum over loose session-*.totals files (verifier-confirmed). external: Stop/SessionEnd hooks receive transcript_path like other events (verified); Opower's loss-framed energy reports are the canonical evidence that pricing waste changes behavior more than pricing savings.
Rationale
One schema decision converts the plugin's hardest-won asset (verified attribution) into a reusable data product, closes the truncation gap retroactively (transcripts hold true sizes), and makes the money number auditable — a credibility move no competitor's status bar can match.
Downsides
A third hook registration and a new state format to maintain and migrate. Loss framing can guilt users into disabling the badge rather than changing behavior — wording matters. "Would have saved" figures are estimates and must be labeled as such.

5. Detection that learns: offender memory + content sniffing

Confidence 65%Complexity Medium
Description
The gate's recognition repertoire is a fixed extension list (json|jsonl|ndjson|csv|tsv|log) duplicated in both hooks; anything extensionless, or read via a pipe, walks past it — by design, because widening the static pattern-match is fragile. Add feedback loops instead. (a) Offender memory: Dangi's file-aware nudge already identifies the exact path that burned context; append it to a learned offender list in the state dir that the gate consults, so any file that hurt once is gated on its next access regardless of extension — with a decay rule so stale entries don't over-block. (b) Content sniff: for large files that fail the extension match, head -c 512 and score structure (leading {/[, delimiter density, line-length uniformity) before deciding. (c) Later: per-type observed compression ratios from hcat's stats ledger tune the advice — this leg first requires adding a path/extension field to hcat's event schema, which it currently lacks.
Basis
direct: hcat-gate.sh:38-39 extension allowlist and dangi-hook.sh:117-123 file-aware path extraction (both verifier-confirmed); the grounding names the narrow-gate misses (cat file | jq) as a stated limitation. reasoned: immune systems work because the infection log feeds the recognition library; here that feedback loop costs one small state file and one extra case-match.
Rationale
Closes the narrow-gate gap without widening the fragile static match — the exact reason it was kept narrow. A self-calibrating gate is also a moat: every competitor in the research ships fixed heuristics.
Downsides
Learned state introduces new failure modes (stale over-blocking, surprising gate behavior the user didn't configure); needs a visible way to inspect and clear the learned list. Sniffing has false positives on prose-ish files.

6. Golden-test the hooks via a shared fixtures library

Confidence 85%Complexity Low
Description
test.sh already contains a purpose-built fixture vocabulary — hook_input (synthetic PostToolUse stdin), gate_input (PreToolUse stdin), compress_event, quote_event/genuine_event (receipt-lookalike vs real) — but it's locked inside a 1264-line statusline-only monolith. Extract test/fixtures.sh and add per-component golden tests for dangi-hook.sh, hcat-gate.sh, doctor.sh, and bin/hcat: deny fires once per file, nudge rate-limits and batches, the hcat-detection regex handles cat file | jq-style edges, doctor verdicts on synthetic settings files. Hooks are ideal test subjects: deterministic stdin-JSON → stdout-JSON, exit-0 programs.
Basis
direct: fixture helper inventory read from test.sh (verifier confirmed the file at 1264 lines with these helpers inline); zero test coverage for the four other executables. reasoned: the repo's own release history — three post-merge hardening passes in v2.5 alone, each citing review findings — is evidence that review-as-test-suite is the expensive path; a fixtures library converts each future finding into a permanent regression test.
Rationale
Every other idea in this document touches the hooks; this is the one that makes all of them cheaper and safer to ship. The attribution logic has already drifted once (the v2.4.1 fix) — precisely the class of bug golden tests pin down.
Downsides
Pure enablement — no user-visible feature ships from this alone. The refactor of test.sh itself needs care not to break the existing 1264 lines of coverage.

7. Retire legacy install mode — doctor --fix becomes a migrator

Confidence 70%Complexity Medium
Description
Doctor openly admits it can only nag about half the legacy surface: "the doctor only edits settings.json; remove them from settings.local.json by hand", and project-level .claude/settings.json files "are not scanned … remove those entries by hand." Two options, in ascending ambition: extend --fix to perform the same jq surgery on settings.local.json and project settings; or declare the next major version plugin-only and turn doctor --fix into a one-shot legacy→plugin migrator (de-register hooks, delete stale copies, verify), after which every dual-mode branch — in scripts, docs, and even Dangi's nudge wording — gets deleted.
Basis
direct: doctor.sh:271 and :365 quoted above — both verifier-confirmed verbatim. The double-firing-hooks failure mode doctor warns about survives exactly in the surfaces it can't fix.
Rationale
Every feature currently pays a two-install-modes tax across scripts, docs, nudge strings, and the test surface. Removal collapses the maintenance matrix and turns doctor from a permanent janitor into a health check for one canonical install.
Downsides
Editing settings.local.json and project files is more invasive than the current user-level-only policy — needs explicit consent UX. Retiring legacy mode strands users who can't (or won't) use the plugin marketplace path; needs a deprecation window.
